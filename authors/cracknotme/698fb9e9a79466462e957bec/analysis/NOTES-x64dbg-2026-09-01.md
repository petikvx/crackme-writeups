# MCM 3.0 — notes session x64dbg 2026-09-01

## Architecture (confirmé live)

- `main` : `argv == "--3a1f9b"` → **child** `sub_1400148C0` ; sinon → **parent** `sub_140011C20`.
- Parent : `CreateProcessA(..., DEBUG_ONLY_THIS_PROCESS)` + cmdline `... --3a1f9b`, puis `WaitForDebugEvent` / `WriteProcessMemory` / `SetThreadContext`.
- Child seul sans injection parent → `GetEnvironmentVariableA("_HEAP_TRACE_FLAGS")` ; si len≠16 → `ExitProcess(rdtsc)`.
- Env `_HEAP_TRACE_FLAGS` = 16 hex → **honeypot** (chemin vers stub INT3 `0x14001A063`), pas le vrai succès.

## Packer / honeypot password

- Packer XOR déjà documenté ; honeypot clair `S3rg0M_Admin_2024` (len 0x11).
- Checksum `xor edi,0x762` : si VM retourne 1, buffer 28 o = `[+] SUCCESS! ACCESS GRANTED.` (somme 0x762). Donc le vrai gate = **VM == 1**.

## Matrice

- Stub INT3 29 o @ `0x14001A050`…`0x14001A06C` : **FNV-1a = `0x412DF8B0`** (identique MCM 2.0).
- Table expected low bytes @ `0x14003BC90`.
- LCG matrice différent de MCM2 (`26125*t - 3233` + NR entre lignes) — à figer vs Hex-Rays/`objdump`.
- Call keygen `0x140011690` : `r9` = seed timing (rdtsc ⊕ …) ; sous parent injecté, seed devrait être forcé (stub FNV / DRx).

## XOR avant VM

```
out[i] = blob[i] XOR key[i % keylen] XOR byte(r13, i%8) XOR byte(r10, i%8)
```
(`(a|b)-(a&b)` = XOR). `r13`/`r10` dérivés anti-debug / injection parent.
