# Guide brute GPU (H100 / CUDA) — alpjs custom VMP

## Pourquoi un H100 peut aider

- 1 candidat = ~1000 itérations de sponge sur **16 octets** (pas de gros état).
- Candidats **indépendants** → embarassingly parallel.
- CPU OpenMP ≈ **10k mdp/s** (8 threads). Un kernel CUDA correct peut viser **10⁶–10⁸+/s** selon l’occupancy.

Ce n’est **pas** hashcat-ready (algo custom). Il faut porter le C.

## Cible à matcher

```text
TAG[8] = e6 a0 ef 22 84 73 41 65
```

(dérivé de RVA `0xC550` : `out[i] = enc[i] ^ ((0x6d + 0x13*i) & 0xff)`)

## Constantes clés

```c
K1 = {0x6c,0x9f,0x1a,0xb7, 0x35,0xe3,0x48,0x7d};  // B628||B62C
K2 = {0x51,0x13,0x2b,0xc7, 0x8e,0xb2,0x4f,0x63};  // B630||B634
K3 = {0xc9,0x3b,0xbd,0x11, 0x94,0x43,0xeb,0xdf};  // B638||B63C
K4 = {0x8d,0x4f,0x67,0x03, 0xca,0xee,0x8b,0x9f};  // B640||B644
```

`C510[64]` : bytes RVA `0xC510` xor-dec comme ci-dessus.  
Précompute `S4[16]` = sponge-absorb des 4 blocs de `C510` (état 0, XOR bloc, 6 rounds `K1/K2` × 4).

## Primitive `rounds(state[16], k1, k2, n)`

Pour `i = 0 .. n-1` :

1. `round_60B0(state, k1, k2, i, 0)`  // moitié basse
2. `round_60B0(state, k1, k2, i, 8)`  // moitié haute
3. `mix_rol(state)`

### `round_60B0(s, k1, k2, a4, a5)` — opère sur `s[a5 .. a5+7]`

```text
swap s[a5+0]↔s[a5+4], …, s[a5+3]↔s[a5+7]
v13 = s[a5+2]
v14 = s[a5+7] + s[a5+1]
v15 = ROL8(s[a5+0]+s[a5+1], s[a5+1]&7)
s[a5+0] = k1[a4] ^ v15
s[a5+1] = ROL8(v14, v13&7)
v16 = s[a5+3]
v18 = ROL8(v13-v16, v16&7)
v19 = k2[a4] ^ v18
s[a5+2] = v19
s[a5+3] = k1[(a4+3)&7] ^ ROL8(v16+v19, s[a5+4]&7)  // s[a5+4] après swap = ancien s[a5+0]
```

Attention : après les swaps, `s[a5+4]` dans le dernier ROL est la valeur **déjà swappée**.

### `mix_rol`

```text
for i in 0..7:
  r = ROL8(s[8+i], s[i]&7)
  s[8+i] = r
  s[i]   = ROL8(s[i], r&7)
```

## Keystretch → MAC[16]

```text
full[40] = pad(password)   # copy + 0x80 at len
v8  = full[0:16]
v81 = full[16:32]
v82 = full[32:40]
v7  = 0
repeat 1000:
  st = v8 XOR v7
  rounds(st, K1, K2, 6)
  st ^= v81
  rounds(st, K1, K2, 6)
  st ^= (v82 || 8×0x00)
  rounds(st, K1, K2, 6)
  v7 = st
MAC = v7
```

## Check (len < 16) — chemin GPU prioritaire

```text
st = S4
st ^= MAC
rounds(st, K1, K2, 6)
rounds(st, K1, K2, 6)          # bloc zéros
st ^= {0×8, 0x80, 0×7}         # uint64 LE 128
rounds(st, K1, K2, 6)
st[0] ^= 0xD1; st[1] ^= 0x5E
rounds(st, K3, K4, 8)
OK iff st[0:8] == TAG
```

Pour `len >= 16`, remplacer le « bloc zéros » par `full[16:32]` et le dernier bloc par `full[32:40] || 0x80 || 0×7`.

## Ordre d’indexation (compat `vmp_brute_mt`)

Alphabet `a-z` (n=26), longueur L :

```text
idx → pw[i] = alph[idx % 26]; idx /= 26;   # i = 0 .. L-1
```

Lowercase len5 déjà testé jusqu’à **index 8126464** (reprendre avec `-s 8126464`).

Espaces utiles :

| Espace | Taille | Note |
|---|---|---|
| a-z len5 | 12.0e6 | ~68 % déjà fait CPU |
| a-z len6 | 308e6 | bon premier job H100 |
| a-z len7 | 8.0e9 | H100 ok si kernel ≥1e7/s |
| a-z0-9 len6 | 2.2e9 | |
| printable 95^6 | 735e9 | lourd même GPU |

## Validation du port

Avant le big job :

```bash
# CPU référence
./tools/vmp_brute_mt 'hello world!'   # → NO
# Sur un candidat connu FAUX, MAC doit matcher Unicorn/C :
# hello world! → MAC dace4a994ae2bd9e055fe42d66a87353
```

Comparer MAC + résultat OK/NO sur 10–20 chaînes entre CUDA et `vmp_brute_mt`.

## Checklist H100

1. Précompute `C510`, `TAG`, `S4` une fois (host → constant memory).
2. Kernel : 1 thread = 1 `(len, idx)` ou 1 password buffer.
3. Écrire hits dans un buffer atomique (`FOUND` + string).
4. Reprendre len5 à 8126464, puis len6 a-z, puis élargir charset.
5. Logger throughput (pwd/s) et ETA.

## Anti-patterns

- Ne pas patcher le binaire pour « forcer OK » : le flag post-bloc0 dépend du vrai MAC.
- Ne pas utiliser hashcat modes existants.
- Vérifier endianness des packs `K*` et du `uint64 128` (`80 00 00 00 00 00 00 00`).
